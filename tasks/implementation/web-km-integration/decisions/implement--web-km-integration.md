# Decision record: implement, Knowledge Maintenance in the web app

Developer audit only. Nothing else may link here.

## Preface

Branch `qa-web/km-integration`, based on `qa-web/adapt-screens`. Tickets 01 to 05 (removal part) built so far. Rules in force: minor and standard questions follow the recommendation; destructive or breaking ones halt for the user. Test seams were approved by recommendation: the store behind each screen, the API client's error shape and the dev proxy targets, all with a fake `fetch`; no component tests.

## Decisions

1. Ticket 01: the KM API nests its error as `{error: {code, message, details}}`, unlike the scheduler. The shared API client reads both shapes. Ranked minor. Self-decided.
2. Ticket 01: KM calls go to the main API on port 8000 through a new dev proxy target (`KM_URL`) and rule, ahead of the Express rule. Ranked minor. Self-decided.
3. Ticket 01: the remembered workflow list is keyed by the signed-in email in `localStorage`, not `sessionStorage`, so it survives a new tab. Ranked minor. Self-decided.
4. Ticket 02: the service has no retry or cancel route (only the commit retry through approve exists), and `failure` and `retrying` are always null. Retry and Cancel are shown greyed out as not available yet, matching the plan's rule of never faking unsupported features; the status screen renders `failure` and `retrying` if the API sends them. Ranked standard. Self-decided; ticket 02 was reworded to match. Follow-up for the backend: implement the two endpoints.
5. Ticket 02: polling every 15 seconds (the API's suggested range), pausing while the tab is hidden, stopping at the two review gates and at terminal or failed states. Ranked minor. Self-decided.
6. Ticket 03: the panel opens on "Needing review" (`pending`) and pages 25 at a time. The API filters only by disposition, so "facts that still need action" is the pending filter, not a separate one. Ranked minor. Self-decided; ticket wording kept as the screen's behaviour.
7. Ticket 03: Accept and Reject are enabled only for `pending` facts; Claim is disabled when the fact is already mine, Release unless it is mine. A colleague's claim is shown with its expiry and does not disable Claim or the decisions, since the API lets any reviewer take over. Ranked minor. Self-decided.
8. Ticket 03: after each accept or reject the panel calls `workflowRun.recheck`, so the page follows the workflow on its own after the last fact. Edit, Rework and Reinstate are shown greyed out. Ranked minor. Self-decided.
9. Ticket 04: the API has no preflight for approval, so "offered only when the API allows it" is met by offering Approve at final approval and showing the API's 409 message verbatim when it refuses; the retry of a failed commit is offered only while `retry_available` is true. Ranked standard. Self-decided.
10. Ticket 04: the workflow response carries no counts or run-graph summary, so the completed summary counts facts per disposition through the facts endpoint (one call each, limit 1) and shows `named_graph_uri` as the run graph identity. Ranked minor. Self-decided.
11. Ticket 04: the API does not say why a re-run sent the workflow back; the panel counts accepted facts with `requires_action` (up to 500) and says that a check against the knowledge graph changed them, and marks each "Needs a new decision". Ranked standard. Self-decided; backend follow-up: expose the re-run reason.
12. Ticket 04: the final review reuses the extraction panel with a stage prop; the decidable disposition is `accepted` and decisions carry `review_stage: final_review`. Ranked minor. Self-decided.
13. Ticket 05: removing the Express document, triple and graph endpoints would break Tracing, Overview and Knowledge Graph, which read them. Ranked breaking; halted and the user chose full removal with those screens greyed out as not available yet. Ticket 05 reworded to match. The SQLite tables stay, so the endpoints can be restored by a revert.
14. Ticket 05: removed `ProcessingView`, `UploadDocModal`, `TracingView`, `KnowledgeGraphView`, `server/extract.js`, the documents, triples and graph routes, and the seed's demo-knowledge block. Tracing and Knowledge Graph routes show a shared not-available panel and their nav entries are disabled. Overview keeps image, ontology and activity data; its entity, relationship, document and pipeline figures are greyed out. The `/overview` endpoint is unchanged. Server tests for the removed endpoints were dropped; the ontology test now inserts a triple directly. Ranked standard. Self-decided after the user's go-ahead. Follow-up: `API.md` and `FLOW.md` still describe the removed endpoints.
15. Acceptance run: the extraction review hung on "Loading facts…" because the main API reads the remote database, opening a new connection per store call and making two extra calls per fact. The user chose to fix the backend rather than run on a local database. Ranked standard. Fix committed on `api-contract/backend-fixes` in `AI_NeSy_Framework` (pooled connections plus batched resolution and MEND reads); `api-contract/integration-prototype` was rebased onto it, local only, nothing merged or pushed. The fact list now answers in about 11 s for 25 facts (was minutes); the rest is network round trips to the remote database, about 1 s per store call.
16. Acceptance run: the user skipped the Paviso and FAO runs, having judged the seed run enough proof the path works. Ranked standard. Ticket 05 keeps those two boxes unchecked and its status says so. The seed workflow `74fd8a71-…` is `completed` with 1 accepted, 13 rejected and 18 unresolved facts (unresolved is the designed result of the canonicalize and MEND gates); dev Fuseki holds the run graph (2 provenance triples) and the one accepted fact's graph (2 triples).
17. Fact-list latency: the user moved the remaining query reduction (about nine store calls per page: duplicate `get_workflow`, `upsert_user` write on every request, separate facts, decisions and document reads, the liveness check per pooled call) out of the prototype into a dedicated query-optimization branch in `AI_NeSy_Framework`, based on `Lee`. Ranked standard. Not started.
